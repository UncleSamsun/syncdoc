# SyncDoc 프로젝트 개요

이 프로젝트의 최상위 문서다. 아래 모든 요구·설계·작업은 여기 적힌 목표와 범위로 거슬러 올라간다.

**아직 확정하지 않은 항목이 셋 있다 — 문제, 성공 판단, 제약.** 검사기가 이 세 항목을 오류로 보고하며 채워질 때까지 이 문서는 초안이다. 세 항목이 비어 있는 동안 "무엇을 위해 만드는가"와 "무엇을 보면 됐다고 하는가"가 정해지지 않은 것이므로, 이 문서를 근거로 범위를 늘리거나 줄이지 않는다.

**대상 사용자:** 본인과 초대한 팀원이다. 개인 프로젝트와 팀 프로젝트를 같은 서비스에서 다룬다. 불특정 사용자의 공개 가입은 하지 않는다. 이용자 범위의 확정 내용은 [프로젝트 설정](../../rules/project-settings.md)에 있다.

**목표:** 초대받은 사용자가 GitHub 저장소를 연결하고, 명세에 정의한 작업과 GitHub의 실행 상태를 한 화면에서 자신의 권한 범위 안에서 읽는다. 명세는 저장소의 Markdown에 두고 실행 상태는 GitHub에 두되, 두 원천을 연결해 조회한다. 어느 쪽도 다른 쪽에 수동으로 복사하지 않는다.

**포함 범위:** [기능과 인수 기준](mvp-scope.md)의 REQ-001 ~ REQ-008이다.

| 요구 | 내용 |
|---|---|
| REQ-001 | 초대와 로그인 |
| REQ-002 | 프로젝트 연결 |
| REQ-003 | 현황과 작업 |
| REQ-004 | 문서 읽기 |
| REQ-005 | 다이어그램 |
| REQ-006 | GitHub 변경 반영 |
| REQ-007 | 접근 범위 |
| REQ-008 | 공통 작성 규칙 |

**제외 범위:** 아래는 MVP에 넣지 않는다. 각 항목의 근거는 [기능과 인수 기준](mvp-scope.md)에 있다.

| 제외 | 이유 |
|---|---|
| 웹에서 문서 편집 | 첫 버전은 읽기·집계에 집중한다. 편집은 저장소에서 한다 |
| 공개 가입 | 이용자를 본인과 초대한 팀원으로 제한한다 |
| 결제·복잡한 조직 관리 | MVP 이용자 범위에 필요하지 않다 |
| 서비스 내부 Issue 발행 자동화 | Issue 발행은 승인된 GitHub 협업 작업이며 읽기 API로 구현하지 않는다 |
| 조직 전체 규칙 자동 배포 | 프로젝트는 고정된 규칙 버전을 쓴다 |
| 기준 자체의 저작·편집 화면 | 기준의 정본은 저장소의 규칙 파일이고 서비스는 준수 여부만 보여준다 |

**적용 Spec:** 이 프로젝트가 쓰는 문서 종류와 적용 여부는 [프로젝트 설정](../../rules/project-settings.md)의 적용 Spec 표 한 곳에서 관리한다. 현재 `tech-ops` 하나가 보류이며 사유는 그 표에 있다. 종류별 필수 내용은 [문서 작성 규칙](../../rules/spec-writing.md)을 따른다.

**용어:** 이 프로젝트에서 아래 말을 이 뜻으로만 쓴다. 하위 문서는 같은 뜻으로 쓰고 다시 정의하지 않는다.

| 말 | 뜻 |
|---|---|
| 프로젝트 | 연결한 GitHub 저장소 하나. 저장소 하나가 프로젝트 하나다 |
| 명세 | `docs/` 아래의 문서. 요구·설계·작업을 정의한다 |
| 규칙 | `rules/` 아래의 문서. 명세를 어떻게 쓰고 협업하는지를 정한다 |
| 산출물 | 프로젝트가 만들어야 하는 문서와 구현물 |
| revision | 저장소의 커밋 하나 |
| snapshot | 특정 revision에서 수집·변환해 게시한 문서 묶음. 서로 다른 revision의 문서를 섞어 게시하지 않는다 |
| 문서 작성 상태 | 문서 frontmatter의 `status`. 초안·검토·확정·폐기 |
| 작업 진행 상태 | GitHub Issue와 Project의 상태. 문서 작성 상태와 다른 값이다 |
| 확정 작업 | 명세에 확정으로 정의한 작업. Issue 등록 여부와 무관하다 |
| 미등록 | 명세의 확정 작업 중 Issue가 없는 것. 완료율 분모에서 빠지지 않는다 |
| 개발 완료 | `dev` 병합과 인수 조건 충족. 릴리스·배포 성공과 다른 값이다 |
