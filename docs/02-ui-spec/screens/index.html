SyncDoc 화면 정의

B안(운영 콘솔) 골격을 Codex 계열 밝은 테마로 다시 그린 구현 기준입니다. 이 페이지의 레이아웃·토큰·상태 문구가 명세의 근거이며, 여기 없는 화면은 MVP 범위가 아닙니다.

골격 B안 · 운영 콘솔 서체 Pretendard 결 Codex 계열 · 단색 우선 테마 밝은 테마 단일
글자는 라틴·숫자·한글 모두 Pretendard를 씁니다. SIL OFL이며 같은 폴더의 fonts/PretendardVariable.woff2를 참조하므로 외부 요청 없이 어느 환경에서 열어도 같은 글자로 보입니다. 이 페이지는 명세의 시각 참조이고 ui-conventions.md·ui-screens.md가 정본입니다.

중성색은 약하게 따뜻한 쪽(#F7F7F5 / #E7E7E4)으로 잡고 글자는 순수한 근검정을 씁니다. 유일한 유채색인 상태색이 차가운 쪽이라 이 대비가 상태를 더 도드라지게 합니다. 상태마다 의미색 + 연한 틴트를 짝지어 씁니다. 색은 세 단계로 나뉘는데, 막대와 범례에는 채움 단계, 흰 바탕의 점과 글자에는 한 단 짙은 글자 단계, 칩·카드·배너 바탕에는 틴트 단계를 씁니다. 글자 단계는 자기 틴트 위에서 4.59~5.32:1로 AA를 넘기고, 막대 채움 단계는 인접 세그먼트가 색약 조건에서 구분됩니다(최악 인접 진행↔미착수 ΔE 17.4 protan). 미착수 무채색과 리뷰 노랑은 흰 바탕 대비가 3:1 미만이라 반드시 글자 라벨·범례 숫자와 함께 둡니다. 예약색은 의미로 갈라 씁니다 — 동기화가 실패한 상태는 실패 빨강, 아직 수집 중이라 값이 확정되지 않은 상태만 주의 주황입니다. 어느 화면에서도 색 하나만으로 상태를 전달하지 않습니다.

02

공통 셸

상단바 44 + 사이드바 212 + 본문. 모든 화면이 이 셸 안에 들어갑니다.

03

UI-001 프로젝트 홈

프로젝트를 고르고 들어가는 화면입니다. 저장소 연결도 여기서만 합니다. 제품 표식을 누르면 언제든 돌아옵니다.

04

UI-002 현황

B안의 본체입니다. 동기화 상태·집계·작업 매핑이 한 화면에 상주합니다.

05

UI-003 문서 본문

사이드바 문서 트리는 셸에 상주하므로 그대로 두고, 본문과 우측 목차만 바뀝니다. 본문 폭은 68자에서 끊습니다.

06

UI-004 검색

현재 프로젝트의 제목·본문만 대상입니다. 결과에도 권한이 적용됩니다.

07

상태 화면

인수 기준이 직접 요구하는 화면입니다. 문구도 여기 적힌 그대로 씁니다.

로그인UI-005
SyncDoc 초대받은 GitHub 계정으로 로그인하세요. 이메일 가입·공개 가입 없음

로그인 외 공개 진입점을 두지 않는다. 세션·토큰을 화면이나 브라우저 저장소에 노출하지 않는다.

미초대 계정UI-006
이 계정은 아직 초대되지 않았습니다 GitHub 로그인은 확인되었지만 서비스 이용이 허용되지 않았습니다. 관리자에게 GitHub 계정 등록을 요청하세요.

로그인 통과가 가입이 아니다. 프로젝트의 존재 여부도 알려주지 않는다.

첫 동기화 대기UI-007
첫 수집을 기다리는 중 저장소를 연결했습니다. 문서 목록은 첫 수집이 끝나면 나타납니다. items [] · snapshotId null · 상세 409 DOCUMENTS_NOT_READY

빈 목록을 "문서가 없음"으로 쓰지 않는다. 대기와 없음은 다른 문구를 쓴다.

갱신 실패 · 오래된 정보UI-008
14:22 기준 정보입니다 · 이후 갱신 실패재시도 14:41
아래 내용은 마지막으로 성공한 snapshot입니다. 실패한 수집이 이 데이터를 덮어쓰지 않았습니다.
docs/04-tasks/implementation-plan.md14:22
errorCode: GITHUB_UNAVAILABLE

마지막 정상 snapshot을 유지하되 최신이라고 말하지 않는다. 오류 문구에 토큰·내부 경로를 넣지 않는다.

Project 조회 불가UI-009
조회 불가progress: null
이 계정으로 연결된 GitHub Project를 조회할 수 없습니다. Project 기반 완료율은 표시하지 않습니다. 문서와 Issue 현황은 그대로 사용할 수 있습니다. 저장소 권한과 Project 권한은 따로 확인됩니다

0%로 대체하지 않고 빈 막대도 그리지 않는다 — 빈 막대는 0%로 읽힌다.

집계 미완UI-010
2 / 6 확정 아님 전체 페이지 수집이 끝나지 않았습니다. 지금 값은 수집된 범위의 중간 집계입니다.
partial: true — counts·progress는 수집 완료 범위만

숫자를 숨기지도 않고 확정으로 쓰지도 않는다. 부분 수집을 완료된 집계로 보이게 하지 않는다.

문서 권한 없음 · 없는 문서UI-011
이 문서를 찾을 수 없습니다 경로가 바뀌었거나 접근 권한이 없습니다. 문서 목록에서 다시 찾아보세요. 404 — 비공개 대상과 없는 대상을 구분하지 않음

권한 없는 비공개 문서와 없는 문서는 같은 문구·같은 404다. 존재를 알려주는 차이를 만들지 않는다.

회수된 snapshotUI-012
이 버전은 더 이상 제공되지 않습니다410
링크가 가리키는 snapshot이 회수되었습니다. 현재 게시본으로 이동할 수 있습니다. 이전 snapshot URL도 현재 권한을 다시 확인합니다

막다른 길을 만들지 않는다. 항상 최신 목록으로 돌아가는 길을 준다.

09

명세에 아직 못 박은 것

구현을 막지는 않지만 확정되면 명세를 고칩니다.

1
연결 설정과 프로젝트 추가의 자리

사이드바 섹션이 문서로 바뀌면서 두 동작을 옮겼습니다 — 연결 설정은 상단바 우측 톱니바퀴, 저장소 연결은 프로젝트 홈의 주 버튼. 문서 섹션 머리에는 건수만 두고 동작 버튼을 두지 않았습니다. 다른 자리를 원하면 알려주세요.

2
동기화 폴링 주기의 화면 반응

설계값은 화면을 보는 동안 20초입니다. 갱신될 때 화면을 조용히 바꿀지, "새 버전 있음 · 새로 고치기"를 띄울지 정해야 합니다. 문서를 읽는 중 본문이 바뀌면 읽던 자리를 잃습니다.

3
모바일 폭

720px 이하에서 사이드바를 드로어로 바꾸는 것까지만 정했습니다. 현황 12열 격자와 6열 표를 좁은 화면에서 어떻게 접을지는 실제 사용 여부를 보고 정하는 편이 낫습니다.

모든 수치·문서 목록·Issue 번호는 fixture 샘플입니다. 실제 GitHub 조회 결과가 아닙니다.

제품 코드는 아직 없습니다. frontend/는 생성되지 않았고 이 페이지는 구현 기준 목업입니다 — 실행되는 React 앱이 아닙니다.
