# 공통 UI 규칙

근거 요구는 [MVP 기능과 인수 기준](../01-prd/mvp-scope.md)의 REQ-001·REQ-003·REQ-004·REQ-005·REQ-006·REQ-007, 데이터 출처는 [MVP API 계약](../03-tech-spec/api-spec.md)이다. 화면별 정의는 [화면 명세](ui-screens.md)에 있다.

이 문서에 적힌 값은 그대로 구현한다. 여기 없는 색·서체·컴포넌트는 만들지 않는다. 새 값이 필요하면 이 문서를 먼저 고친다.

## 1. 적용 범위

- 밝은 테마 하나만 구현한다. 어두운 테마와 테마 전환 장치를 만들지 않는다.
- 단색이 기본이고 유채색은 상태 표시에만 쓴다. 브랜드 강조색을 따로 두지 않는다.
- 화면에 유채색이 보이면 그것은 항상 상태다. 장식·구분·강조 목적으로 상태색을 쓰지 않는다.

## 2. 색 토큰

| 토큰 | 값 | 용도 |
|---|---|---|
| `--bg` | `#FFFFFF` | 본문 바탕 |
| `--sunk` | `#F7F7F5` | 사이드바, 표 머리, 가라앉은 면 |
| `--hover` | `#F1F1EE` | 행·항목 hover |
| `--line` | `#E7E7E4` | 기본 경계선 |
| `--line2` | `#D5D5D0` | 강한 경계선, 입력 테두리 |
| `--ink` | `#0D0D0D` | 본문 글자 |
| `--ink2` | `#5B5B57` | 보조 글자 |
| `--ink3` | `#8C8C86` | 흐린 글자, 라벨 |
| `--act` / `--on-act` | `#0D0D0D` / `#FFFFFF` | 주 동작 버튼 |
| `--ring` | `#2F6FAA` | 키보드 초점 링 |

중성색은 약하게 따뜻한 쪽이고 글자는 순수한 근검정이다. 이 조합을 임의로 회색 계열로 바꾸지 않는다.

## 3. 상태 색과 형태

상태마다 **의미색 + 연한 틴트**를 짝지어 쓴다. 색은 세 단계로 나눈다 — 막대와 범례에는 채움 단계, 흰 바탕의 점과 글자에는 한 단 짙은 글자 단계, 칩·카드·배너 바탕에는 틴트 단계.

| 상태 | 채움(막대·범례) | 글자(점·라벨·테두리) | 틴트(바탕) |
|---|---|---|---|
| 미착수 | `--st-todo` `#9AA1A8` | `--st-todo-ink` `#5F656B` | `--st-todo-bg` `#EDEEEF` |
| 진행 | `--st-prog` `#1176CE` | `--st-prog-ink` `#0A64AC` | `--st-prog-bg` `#E1F0FC` |
| 리뷰 | `--st-rev` `#E8AE2A` | `--st-rev-ink` `#8A5D04` | `--st-rev-bg` `#FBF0CE` |
| 완료 | `--st-done` `#14803D` | `--st-done-ink` `#127036` | `--st-done-bg` `#DEF3E5` |
| 정상 · 동기화 성공 | — | `--st-done-ink` `#127036` | `--sf-ok` `#F0FAF4` |
| 주의 · 집계 미확정 | — | `--warn` `#B85408` | `--sf-rev` `#FFF6EF` |
| 실패 · 동기화 실패 | — | `--st-fail` `#D0392A` | `--sf-fail` `#FFF4F3` |

| 상태 | 형태 |
|---|---|
| Issue 미등록 | 1px 점선 테두리, 채움 없음, 글자 `--ink3` |
| 취소 · 분모 제외 | `--st-todo-bg` 바탕 + 1px 실선 테두리 + 45° 해치(`--line2`, 2px/5px), 글자 `--st-todo-ink` |

`--sf-info #F2F4F5`는 상태가 아닌 안내 배너 바탕이다.

### 지켜야 할 것

- 상태를 색만으로 전달하지 않는다. 점·칩·막대 어디서든 글자 라벨을 함께 붙인다.
- 글자 단계는 자기 틴트 위에서 4.5:1 이상을 유지한다(현재 4.59~5.32:1). 틴트 위에 채움 단계를 글자로 쓰지 않는다.
- 막대 채움 단계는 인접 세그먼트가 색약 조건에서 구분되어야 한다(현재 최악 인접 진행↔미착수 ΔE 17.4 protan, 정상 시각 20.6). 값을 바꿀 때 인접 구분을 다시 확인한다.
- 미착수 무채색과 리뷰 노랑은 흰 바탕 대비가 3:1 미만이다. 이 두 색이 쓰인 곳에는 반드시 글자 라벨이나 범례 숫자가 함께 있어야 한다.
- 주의와 실패는 예약색이다. 작업 상태에 이 두 색을 쓰지 않고, 반대로 주의·실패에 작업 상태색을 쓰지 않는다.
- 예약색은 의미로 갈라 쓴다. **동기화가 실패한 상태는 실패 빨강**이다 — 동기화 카드, 상단바 동기화 칩, 오래된 정보 배너, 다이어그램 렌더 실패가 모두 여기에 해당한다. 주의 주황은 **아직 수집 중이라 값이 확정되지 않은 상태**에만 쓴다(집계 미확정 칩).
- 예약색을 탁한 갈색·겨자색으로 낮추지 않는다. 선명한 색조를 유지하고, 대비가 부족하면 색을 어둡게 하는 대신 틴트를 밝게 조정한다.
- 초점 링 `--ring`은 상태색이 아니다. 상태 표현에 쓰지 않는다.
- "없음"과 "제외"는 색을 새로 만들지 않고 점선·해치로 구분한다.

## 4. 글자

- 본문·UI 서체는 **Pretendard**다. 라틴·숫자·한글을 모두 이 서체로 그린다. `pretendard` 패키지 v1.3.9의 가변 woff2(`dist/web/variable/woff2/PretendardVariable.woff2`)를 앱에서 self-host하고 `font-weight: 100 900`, `font-display: swap`으로 선언한다. 외부 CDN에서 불러오지 않는다. SIL Open Font License다.
- 대체 스택은 `system-ui, -apple-system, 'Apple SD Gothic Neo', 'Malgun Gothic', sans-serif`다.
- 라틴만 다른 서체로 갈라 받게 하지 않는다. 서체를 하나로 두면 혼용 라인의 베이스라인·x높이·자간을 따로 맞출 필요가 없다.
- 고정폭 서체는 self-host한 JetBrains Mono를 쓰고 대체 스택은 `ui-monospace, SFMono-Regular, Consolas, monospace`다. 패키지와 버전은 첫 구현에서 lock에 고정한다.
- 고정폭은 식별자에만 쓴다 — snapshot id, revision, 저장소 경로, 파일 경로, TASK·Issue·PR 번호, 시각, 코드, 오류 코드. 일반 문장에 쓰지 않는다.

| 항목 | 값 |
|---|---|
| 글자 크기 | 11 · 12 · 13 · 14.5 · 16 · 18 · 23 · 25 |
| 기본 크기 | UI 13, 문서 본문 14.5, 지표 숫자 23 |
| 굵기 | 400 · 500 · 600 (700 이상 사용 금지) |
| 행간 | UI 1.5, 문서 본문 1.78 |
| 본문 폭 | 68자에서 끊는다 |
| 라벨 | 11px, 자간 0.02em |
| 숫자 | 열에 정렬되는 숫자는 `font-variant-numeric: tabular-nums` |

## 5. 간격 · 형태 · 밀도

| 항목 | 값 |
|---|---|
| 간격 단위 | 4 · 8 · 12 · 16 · 20 · 26 · 34 |
| 카드 안쪽 | 13px 15px |
| 카드 사이 | 12 |
| 모서리 | 입력·버튼 6, 카드·표 8, 칩·상태 막대 999, 작은 표식 4 |
| 표 행 높이 | 36 |
| 목록 행 높이 | 30 |
| 상단바 높이 | 44 |
| 사이드바 폭 | 212 |
| 격자 | 12열, 열 간격 12 |
| 그림자 | 사용하지 않는다. 사이드바 활성 항목과 떠 있는 요소만 `0 1px 2px rgba(0,0,0,.04)` |

카드는 선으로만 구분한다. 모든 블록에 같은 테두리·모서리·그림자를 일괄 적용하지 않는다.

## 6. 공통 컴포넌트

| 컴포넌트 | 정의 |
|---|---|
| 상태 점 + 라벨 | 6px 원 + 글자. 점과 글자 모두 그 상태의 글자 단계 색을 쓴다. 표 안의 상태는 이 형태만 쓰고 색면 칩을 쓰지 않는다 |
| 예외 칩 | 높이 20, 모서리 999. 미등록은 점선, 취소는 중립 틴트 + 해치, 미확정은 `--warn` 테두리와 `--sf-rev` 바탕 |
| 버튼 | 높이 28(작은 것 24), 모서리 6. 주 동작은 `--act` 채움 하나만 두고 나머지는 테두리 버튼 |
| 아이콘 버튼 | 22px 정사각, 모서리 5. 평상시 테두리 없이 `--ink3`, hover에서 `--bg` 바탕과 `--line` 테두리. 상단바 우측의 연결 설정에만 쓴다. `aria-label`과 `title`을 반드시 붙인다 |
| 배너 | 화면 폭 전체. 실패(`--sf-fail` 바탕 + `--st-fail` 테두리·글자)와 주의(`--sf-rev` + `--warn`) 두 종류만. 동기화 실패는 실패 배너를 쓴다 |
| 지표 카드 | 라벨 11 + 숫자 23 + 기준 문구. 분모나 집계 기준 없이 숫자만 두지 않는다 |
| 상태 스택바 | 높이 10, 세그먼트마다 모서리 999 알약, 간격 3, 색은 채움 단계. 막대 안에 숫자를 넣지 않고 아래 범례에 8px 원형 스와치 · 라벨 · 건수를 둔다 |
| 데이터 표 | 머리 28 / 행 36, 머리 바탕 `--sunk`. 식별자 열은 고정폭 |
| 동기화 칩 | 상단바 우측 상주. 성공과 실패가 같은 형식이고 색만 다르다 — 성공은 `--sf-ok` 바탕 + `--st-done-ink` 테두리·글자·점, 실패는 `--sf-fail` 바탕 + `--st-fail` 테두리·글자·점 |
| 골격 로딩 | 높이 10 막대. 목록·본문 자리를 미리 잡아 화면 밀림을 막는다 |
| 제품 표식 | [강아지 마크](../../outputs/logo/syncdoc-dog-logo.svg) + `SyncDoc` 글자. 마크는 단일 path에 `fill-rule="evenodd"`이며 `fill`은 `currentColor`로 두어 `--act` 하나만 쓴다. 흰 부분은 도형의 구멍이라 페이지 바탕이 비치므로 흰 면 위에만 놓는다. 배경 사각형을 넣지 않고 여백을 잘라낸 `viewBox="171 360 912 495"`(비율 1.84)를 쓴다. 상단바에서 마크 가로 30px. 색을 넣거나 그러데이션을 쓰지 않고, 마크를 다시 그리지 않는다 — 이 파일이 정본이다. 마크는 프로젝트 홈 링크를 겸한다 |
| 문서 트리 | 접을 수 있는 폴더 줄(높이 27, 펼침 표식 + 폴더 아이콘 13px + 이름 + 건수, 구분선 없음)과 안내선으로 들여쓴 문서 항목. 활성 문서는 흰 바탕 + 테두리, 그 문서가 든 폴더는 글자 색만 `--ink`로 올리고 굵기는 그대로 |

아이콘은 16px 선 SVG를 쓴다. 이모지를 아이콘으로 쓰지 않는다.

## 7. 탐색

- 모든 화면은 상단바(44) + 사이드바(212) + 본문 셸 안에 들어간다.
- 사이드바 이동 항목은 현황 · 작업 · 검색 셋이다. 항목을 늘리지 않는다.
- 그 아래 `문서` 섹션 머리(오른쪽에 문서 건수)와 문서 트리를 둔다. 트리는 셸의 일부이므로 어느 화면에서도 자리를 지키며, 화면이 바뀌어도 사이드바가 다른 내용으로 교체되지 않는다.
- `문서` 섹션 머리에는 건수만 둔다. 동작 버튼을 두지 않는다.
- 프로젝트 전환은 상단바의 스위처로 한다. 프로젝트를 고르고 저장소를 연결하는 일은 프로젝트 홈이 전담한다. 제품 표식을 누르면 프로젝트 홈으로 간다.
- 연결 설정은 상단바 우측의 톱니바퀴 아이콘 버튼으로 연다. 사이드바에 두지 않는다.
- 문서 기준 브랜치도 상단바에서 바꾼다. 기본값은 `main`이다. 브랜치 전환의 권한·수집 처리는 [화면 명세](ui-screens.md)의 UI-000을 따른다.
- 브라우저 뒤로 가기는 직전 화면으로 돌아간다. 문서·검색·작업 화면은 URL로 직접 열 수 있다.
- 1040px 이하에서 사이드바를 아이콘 48px로 접고, 720px 이하에서는 상단 드로어로 바꾼다.

## 8. 접근성

- 본문 글자와 바탕의 명암비는 4.5:1 이상을 유지한다.
- 키보드 초점은 `--ring` 2px 윤곽으로 항상 보이게 한다. 초점 표시를 제거하지 않는다.
- 누를 수 있는 요소의 높이는 24px 이상으로 두고 서로 8px 이상 띄운다.
- 상태 막대·다이어그램에는 값과 단위를 담은 대체 텍스트를 붙인다.
- 표에는 머리 행을 두고 정렬 가능한 열은 정렬 상태를 글자로도 알린다.
- `prefers-reduced-motion: reduce`에서 전환과 애니메이션을 끈다.
- 넓은 내용(표·코드·다이어그램)은 자기 컨테이너에서 가로 스크롤한다. 페이지 본문이 가로로 밀리지 않는다.

## 9. 공통 상태 표현

| 상황 | 표현 |
|---|---|
| 불러오는 중 | 골격 로딩. 회전 표식으로 대체하지 않는다 |
| 값이 없음(권한·조회 불가) | 점선 테두리 + "조회 불가" 글자. 0이나 빈 막대를 그리지 않는다 |
| 집계 미확정 | 숫자 옆에 "확정 아님" 칩. 숫자를 숨기지 않는다 |
| 오래된 데이터 | 화면 상단 주의 배너 + 기준 시각. 최신이라고 쓰지 않는다 |
| 실패 | 실패 배너 + 마지막 성공 시각 + 오류 코드 |
| 비어 있음 | 원인을 구분한 문구와 다음 행동 버튼. "데이터 없음"으로 합치지 않는다 |
| 권한 없음 · 없는 대상 | 같은 문구, 같은 404. 존재 여부를 알려주는 차이를 만들지 않는다 |

문구는 사용자가 무엇이 일어났고 다음에 무엇을 할 수 있는지 알 수 있게 쓴다. 사과하지 않고 내부 용어를 쓰지 않는다. 상태 화면별 확정 문구는 [화면 명세](ui-screens.md)에 있다.

## 10. 하지 않는 것

- 세션 식별자·GitHub 토큰·설치 토큰을 화면이나 브라우저 저장소에 두지 않는다. 브라우저 저장소에는 화면 상태(문서 트리 폴더 접힘 등)만 두고, 문서 내용과 집계 결과도 담지 않는다.
- 오류 문구·진단 표시에 토큰과 서버 내부 경로를 넣지 않는다.
- 문서 편집·서비스 내부 Issue 생성 진입점을 만들지 않는다.
- 서버가 정화한 html 밖의 원문 Markdown을 화면에서 직접 해석하지 않는다.
- 다이어그램 원문을 코드로 평가하지 않는다. 문서 원문의 Mermaid 설정 지시를 적용하지 않는다.
- 커밋 수·PR 수를 완료율로 환산하지 않는다.
- 백엔드가 없는 동안 쓰는 fixture 값을 실제 GitHub 조회 결과로 표시하지 않는다.
