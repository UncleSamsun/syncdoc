# 공통 UI 규칙

근거 요구는 [MVP 기능과 인수 기준](../01-prd/mvp-scope.md)의 REQ-001·REQ-003·REQ-004·REQ-005·REQ-006·REQ-007, 데이터 출처는 [MVP API 계약](../03-tech-spec/api-spec.md)이다. 화면별 정의는 [화면 명세](ui-screens.md)에 있다.

이 문서에 적힌 값은 그대로 구현한다. 여기 없는 색·서체·컴포넌트는 만들지 않는다. 새 값이 필요하면 이 문서를 먼저 고친다.

## 1. 적용 범위

- Codex 톤의 중성 회색 다크 테마 하나를 구현한다. 테마 전환 장치는 이번 범위에 포함하지 않는다.
- 단색이 기본이고 유채색은 상태 표시에만 쓴다. 브랜드 강조색을 따로 두지 않는다.
- 화면에 유채색이 보이면 그것은 항상 상태다. 장식·구분·강조 목적으로 상태색을 쓰지 않는다.

## 2. 색 토큰

| 토큰 | 값 | 용도 |
|---|---|---|
| `--bg` | `#1E1E1E` | 본문 바탕 |
| `--sunk` | `#181818` | 사이드바, 표 머리, 가라앉은 면 |
| `--hover` | `#2B2B2B` | 행·항목 hover |
| `--line` | `#333333` | 기본 경계선 |
| `--line2` | `#454545` | 강한 경계선, 입력 테두리 |
| `--ink` | `#E6E6E6` | 본문 글자 |
| `--ink2` | `#B8B8B8` | 보조 글자 |
| `--ink3` | `#A6A6A6` | 흐린 글자, 라벨 |
| `--act` / `--on-act` | `#E6E6E6` / `#181818` | 주 동작 버튼 |
| `--ring` | `#9EC6E8` | 키보드 초점 링 |

배경은 푸른 기 없는 중성 회색이고 본문은 밝은 회색이다. 순백색 문서 면을 사용하지 않는다. 코드 바탕은 `--code-bg #282828`, 코드 굵기는 400이다.

## 3. 상태 색과 형태

상태마다 **의미색 + 연한 틴트**를 짝지어 쓴다. 색은 세 단계로 나눈다 — 막대와 범례에는 채움 단계, 어두운 바탕의 점과 글자에는 한 단 짙은 글자 단계, 칩·카드·배너 바탕에는 틴트 단계.

| 상태 | 채움(막대·범례) | 글자(점·라벨·테두리) | 틴트(바탕) |
|---|---|---|---|
| 미착수 | `--st-todo` `#9AA1A8` | `--st-todo-ink` `#A6ADB5` | `--st-todo-bg` `#25282C` |
| 진행 | `--st-prog` `#1176CE` | `--st-prog-ink` `#85C4F4` | `--st-prog-bg` `#1B2A35` |
| 리뷰 | `--st-rev` `#E8AE2A` | `--st-rev-ink` `#EDC76C` | `--st-rev-bg` `#332D1F` |
| 완료 | `--st-done` `#14803D` | `--st-done-ink` `#80D79D` | `--st-done-bg` `#1B2C22` |
| 정상 · 동기화 성공 | — | `--st-done-ink` `#80D79D` | `--sf-ok` `#1B2C22` |
| 주의 · 집계 미확정 | — | `--warn` `#EDBD83` | `--sf-rev` `#33291E` |
| 실패 · 동기화 실패 | — | `--st-fail` `#F1968E` | `--sf-fail` `#352422` |

| 상태 | 형태 |
|---|---|
| Issue 미등록 | 1px 점선 테두리, 채움 없음, 글자 `--ink3` |
| 취소 · 분모 제외 | `--st-todo-bg` 바탕 + 1px 실선 테두리 + 45° 해치(`--line2`, 2px/5px), 글자 `--st-todo-ink` |

`--sf-info #252525`는 상태가 아닌 안내 배너 바탕이다.

### 지켜야 할 것

- 상태를 색만으로 전달하지 않는다. 점·칩·막대 어디서든 글자 라벨을 함께 붙인다.
- 글자 단계는 자기 틴트 위에서 4.5:1 이상을 유지한다. 틴트 위에 채움 단계를 글자로 쓰지 않는다.
- 막대 채움 단계는 인접 세그먼트가 색약 조건에서 구분되어야 한다. 값을 바꿀 때 인접 구분을 다시 확인한다.
- 막대·범례와 모든 상태색에는 글자 라벨을 함께 제공한다. 어두운 바탕과 상태 틴트의 대비를 함께 확인한다.
- 주의와 실패는 예약색이다. 작업 상태에 이 두 색을 쓰지 않고, 반대로 주의·실패에 작업 상태색을 쓰지 않는다.
- 예약색은 의미로 갈라 쓴다. **동기화가 실패한 상태는 실패 빨강**이다 — 동기화 카드, 상단바 동기화 칩, 오래된 정보 배너, 다이어그램 렌더 실패가 모두 여기에 해당한다. 주의 주황은 **아직 수집 중이라 값이 확정되지 않은 상태**에만 쓴다(집계 미확정 칩).
- 예약색을 탁한 갈색·겨자색으로 낮추지 않는다. 선명한 색조를 유지하고, 대비가 부족하면 색을 어둡게 하는 대신 틴트를 밝게 조정한다.
- 초점 링 `--ring`은 상태색이 아니다. 상태 표현에 쓰지 않는다.
- "없음"과 "제외"는 색을 새로 만들지 않고 점선·해치로 구분한다.

## 4. 글자

- 본문·UI 서체는 **Pretendard**다. 라틴·숫자·한글을 모두 이 서체로 그린다. `pretendard` 패키지 v1.3.9의 가변 woff2(`dist/web/variable/woff2/PretendardVariable.woff2`)를 앱에서 self-host하고 `font-weight: 100 900`, `font-display: swap`으로 선언한다. 외부 CDN에서 불러오지 않는다. SIL Open Font License다.
- 대체 스택은 `system-ui, -apple-system, 'Apple SD Gothic Neo', 'Malgun Gothic', sans-serif`다.
- 라틴만 다른 서체로 갈라 받게 하지 않는다. 서체를 하나로 두면 혼용 라인의 베이스라인·x높이·자간을 따로 맞출 필요가 없다.
- 고정폭 서체는 self-host한 JetBrains Mono v2.304 Regular/Medium/SemiBold를 쓰고 대체 스택은 `Consolas, ui-monospace, monospace`다. 원본 출처·버전·라이선스는 `frontend/public/fonts/README.md`에서 관리한다.
- 고정폭은 식별자에만 쓴다 — snapshot id, revision, 저장소 경로, 파일 경로, TASK·Issue·PR 번호, 시각, 코드, 오류 코드. 일반 문장에 쓰지 않는다.

| 항목 | 값 |
|---|---|
| 글자 크기 | 12 · 13 · 14 · 15 · 16.5 · 18 · 20 · 24 · 26 · 28 |
| 기본 크기 | UI 15, 문서 본문 16.5, 지표 숫자 26 |
| 최소 크기 | 12. 라벨·건수·식별자도 이보다 작게 쓰지 않는다 |
| 굵기 | 400 · 500 · 600 (700 이상 사용 금지) |
| 행간 | UI 1.5, 문서 본문 1.78 |
| 본문 폭 | 68자에서 끊는다 |
| 라벨 | 탐색 라벨·폴더명은 UI 서체 13px/500, 건수도 13px/500. 본문 보조 정보는 최소 13px이며 `--ink2` 또는 읽을 수 있는 보조색을 쓴다 |
| 숫자 | 열에 정렬되는 숫자는 `font-variant-numeric: tabular-nums` |

2026-09-21에 스케일을 한 단 올렸다. 이전 값(UI 13 · 본문 14.5 · 최소 10)은 실제 화면에서 읽기 어렵다는 사용자 확인이 있었다. 비율은 그대로 두고 값만 올렸으므로 화면 밀도의 성격은 바뀌지 않는다.

### 문서 제목과 강조의 구분

- H1은 문서 제목 하나이며 28px/600이다. H2는 큰 구획으로 24px/600, 위 48px·아래 18px, 아래 구분선과 10px 안쪽 여백을 둔다.
- H3은 H2 안의 세부 구획으로 20px/600, 위 32px·아래 14px이다. H4는 18px/600, 위 24px·아래 10px이다. H3/H4와 모든 문단에 구분선을 반복하지 않는다. 목차 들여쓰기도 제목 단계에 맞춘다.
- 여러 빈 줄을 넣는 방식에 의존하지 않는다. 제목·문단의 여백은 모든 저장소에 같은 렌더 규칙을 적용한다. 문서의 첫 구획은 위 여백을 줄인다.
- 중요한 일반 개념은 `strong`으로 600 굵기를 쓴다. 인라인 `code`는 실제 식별자·명령·값을 표시하며 JetBrains Mono 400, 본문 글자색과 구분되는 바탕/테두리로 읽는다. 코드 블록도 400으로 표시하고 인라인 배지를 반복하지 않는다.
- 숫자 정렬이 필요하면 `font-variant-numeric: tabular-nums`를 쓰며 일반 라벨을 고정폭 글꼴로 바꾸지 않는다.

### 스크롤 영역

상단바는 viewport 위쪽에 유지하고 사이드바·본문은 각각 아래에서 스크롤한다. 문서 목차는 본문 영역 안에서 sticky다. 항목이 넘치면 너비와 무관하게 상단바가 줄바꿈하며 긴 저장소·경로는 줄이고 전체 값을 tooltip으로 확인한다. 좁은 화면에서는 탐색 영역의 높이를 제한해 본문을 읽을 공간을 남긴다. 본문 앵커·검색 결과 이동은 고정 상단바 뒤에 가려지지 않는다.

### 산출물 탐색

문서 탐색은 저장소의 폴더 구조 하나로 제공한다. 종류별 화면의 묶음 제목·문서 목록·건수·여백 표현을 폴더 트리에 적용하며 탐색 방식 전환 버튼은 두지 않는다. 폴더 이름과 계층은 저장소 원문을 유지한다. 가장 바깥쪽 세로 안내선과 그 들여쓰기 여백은 제거하고 하위 폴더의 안내선·들여쓰기는 유지한다. 현재 문서가 든 폴더는 펼치고 과거 게시본 링크는 같은 snapshot을 유지한다. 산출물 링크 옆 숫자는 오류일 때 `오류 N`으로 표시하며 오류 0을 산출물 0처럼 표시하지 않는다.

### 테마 검토 범위

사용자가 다크 방향을 검토하고 Codex 톤으로 진행하도록 확정했다. 제품 기본은 중성 회색 다크 테마다. Mermaid도 같은 배경·밝은 글자·중성 선으로 렌더하며 원문이 테마·보안 설정을 덮어쓰지 못하게 한다.

| 카드 사이 | 12 |

## 6. 공통 컴포넌트

| 컴포넌트 | 정의 |
|---|---|
| 상태 점 + 라벨 | 6px 원 + 글자. 점과 글자 모두 그 상태의 글자 단계 색을 쓴다. 표 안의 상태는 이 형태만 쓰고 색면 칩을 쓰지 않는다 |
| 예외 칩 | 높이 22, 모서리 999. 미등록은 점선, 취소는 중립 틴트 + 해치, 미확정은 `--warn` 테두리와 `--sf-rev` 바탕 |
| 버튼 | 높이 32(작은 것 26), 모서리 6. 주 동작은 `--act` 채움 하나만 두고 나머지는 테두리 버튼 |
| 아이콘 버튼 | 24px 정사각, 모서리 5. 평상시 테두리 없이 `--ink3`, hover에서 `--bg` 바탕과 `--line` 테두리. 상단바 우측의 연결 설정에만 쓴다. `aria-label`과 `title`을 반드시 붙인다 |
| 배너 | 화면 폭 전체. 실패(`--sf-fail` 바탕 + `--st-fail` 테두리·글자)와 주의(`--sf-rev` + `--warn`) 두 종류만. 동기화 실패는 실패 배너를 쓴다 |
| 지표 카드 | 라벨 12 + 숫자 26 + 기준 문구. 분모나 집계 기준 없이 숫자만 두지 않는다 |
| 상태 스택바 | 높이 10, 세그먼트마다 모서리 999 알약, 간격 3, 색은 채움 단계. 막대 안에 숫자를 넣지 않고 아래 범례에 8px 원형 스와치 · 라벨 · 건수를 둔다 |
| 데이터 표 | 머리 32 / 행 40, 머리 바탕 `--sunk`. 식별자 열은 고정폭 |
| 동기화 칩 | 상단바 우측 상주. 성공과 실패가 같은 형식이고 색만 다르다 — 성공은 `--sf-ok` 바탕 + `--st-done-ink` 테두리·글자·점, 실패는 `--sf-fail` 바탕 + `--st-fail` 테두리·글자·점 |
| 골격 로딩 | 높이 10 막대. 목록·본문 자리를 미리 잡아 화면 밀림을 막는다 |
| 제품 표식 | [강아지 마크](../../outputs/logo/syncdoc-dog-logo.svg) + `SyncDoc` 글자. 마크는 단일 path에 `fill-rule="evenodd"`이며 `fill`은 `currentColor`로 두어 `--act` 하나만 쓴다. 빈 부분은 도형의 구멍이라 현재 면의 바탕이 비친다. 다크 면에서는 밝은 `currentColor`로 형태를 유지한다. 배경 사각형을 넣지 않고 여백을 잘라낸 `viewBox="171 360 912 495"`(비율 1.84)를 쓴다. 상단바에서 마크 가로 30px. 색을 넣거나 그러데이션을 쓰지 않고, 마크를 다시 그리지 않는다 — 이 파일이 정본이다. 마크는 프로젝트 홈 링크를 겸한다 |
| 문서 트리 | 접을 수 있는 폴더 줄(높이 30, 펼침 표식 + 폴더 아이콘 14px + 이름 + 건수, 구분선 없음)과 안내선으로 들여쓴 문서 항목. 활성 문서는 흰 바탕 + 테두리, 그 문서가 든 폴더는 글자 색만 `--ink`로 올리고 굵기는 그대로 |

아이콘은 16px 선 SVG를 쓴다. 이모지를 아이콘으로 쓰지 않는다.

## 7. 탐색

- 모든 화면은 상단바(기본 50) + 사이드바(248) + 본문 셸 안에 들어간다.
- 사이드바 이동 항목은 현황 · 작업 · 산출물 · 검색이다.
- 그 아래 `문서` 섹션 머리(오른쪽에 문서 건수)와 문서 트리를 둔다. 트리는 셸의 일부이므로 어느 화면에서도 자리를 지키며, 화면이 바뀌어도 사이드바가 다른 내용으로 교체되지 않는다.
- `문서` 섹션 머리에는 건수만 둔다. 동작 버튼을 두지 않는다.
- 프로젝트 전환은 상단바의 스위처로 한다. 프로젝트를 고르고 저장소를 연결하는 일은 프로젝트 홈이 전담한다. 제품 표식을 누르면 프로젝트 홈으로 간다.
- 연결 설정은 상단바 우측의 톱니바퀴 아이콘 버튼으로 연다. 사이드바에 두지 않는다.
- 문서 기준 브랜치도 상단바에서 바꾼다. 기본값은 `main`이다. 브랜치 전환의 권한·수집 처리는 [화면 명세](ui-screens.md)의 UI-000을 따른다.
- 브라우저 뒤로 가기는 직전 화면으로 돌아간다. 문서·검색·작업 화면은 URL로 직접 열 수 있다.
- 720px 이하에서는 탐색 영역을 위쪽에 배치하고 높이를 제한한다. 본문은 남은 공간에서 별도로 스크롤한다.

## 8. 접근성

- 본문 글자와 바탕의 명암비는 4.5:1 이상을 유지한다.
- 키보드 초점은 `--ring` 2px 윤곽으로 항상 보이게 한다. 초점 표시를 제거하지 않는다.
- 누를 수 있는 요소의 높이는 24px 이상으로 두고 서로 8px 이상 띄운다.
- 상태 막대·다이어그램에는 값과 단위를 담은 대체 텍스트를 붙인다.
- 표에는 머리 행을 두고 정렬 가능한 열은 정렬 상태를 글자로도 알린다.
- `prefers-reduced-motion: reduce`에서 전환과 애니메이션을 끈다.
- 넓은 내용(표·코드·다이어그램)은 자기 컨테이너에서 가로 스크롤한다. 페이지 본문이 가로로 밀리지 않는다.

## 9. 공통 상태 표현

| 상황 | 표현 |
|---|---|
| 불러오는 중 | 골격 로딩. 회전 표식으로 대체하지 않는다 |
| 값이 없음(권한·조회 불가) | 점선 테두리 + "조회 불가" 글자. 0이나 빈 막대를 그리지 않는다 |
| 집계 미확정 | 숫자 옆에 "확정 아님" 칩. 숫자를 숨기지 않는다 |
| 오래된 데이터 | 화면 상단 주의 배너 + 기준 시각. 최신이라고 쓰지 않는다 |
| 실패 | 실패 배너 + 마지막 성공 시각 + 오류 코드 |
| 비어 있음 | 원인을 구분한 문구와 다음 행동 버튼. "데이터 없음"으로 합치지 않는다 |
| 권한 없음 · 없는 대상 | 같은 문구, 같은 404. 존재 여부를 알려주는 차이를 만들지 않는다 |

문구는 사용자가 무엇이 일어났고 다음에 무엇을 할 수 있는지 알 수 있게 쓴다. 사과하지 않고 내부 용어를 쓰지 않는다. 상태 화면별 확정 문구는 [화면 명세](ui-screens.md)에 있다.

## 10. 하지 않는 것

- 세션 식별자·GitHub 토큰·설치 토큰을 화면이나 브라우저 저장소에 두지 않는다. 브라우저 저장소에는 화면 상태(문서 트리 폴더 접힘 등)만 두고, 문서 내용과 집계 결과도 담지 않는다.
- 오류 문구·진단 표시에 토큰과 서버 내부 경로를 넣지 않는다.
- 문서 편집·서비스 내부 Issue 생성 진입점을 만들지 않는다.
- 서버가 정화한 html 밖의 원문 Markdown을 화면에서 직접 해석하지 않는다.
- 다이어그램 원문을 코드로 평가하지 않는다. 문서 원문의 Mermaid 설정 지시를 적용하지 않는다.
- 커밋 수·PR 수를 완료율로 환산하지 않는다.
- 백엔드가 없는 동안 쓰는 fixture 값을 실제 GitHub 조회 결과로 표시하지 않는다.
