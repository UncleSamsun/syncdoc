# UI 방향 검토 기록

이 문서는 UI 방향을 정하는 과정에서 검토한 대안과 탈락 이유를 남긴 기록이다. 구현 기준이 아니다. 실제로 구현할 내용은 [공통 UI 규칙](ui-conventions.md)과 [화면 명세](ui-screens.md)에만 있다. 두 문서와 이 기록이 어긋나면 두 문서가 정본이다.

## 검토한 세 방향

| 방향 | 화면 중심 | 최적화 | 포기 |
|---|---|---|---|
| A · 읽기 우선 | 문서 사이트형 3열. 현황은 별도 홈 | 긴 명세·표·다이어그램을 오래 읽는 시간 | 현황이 한눈에 안 들어옴 |
| B · 운영 콘솔 | 12열 현황 격자. 문서는 같은 셸에서 전환 | 동기화 실패·부분 집계·권한 부족이 상주 | 본문 폭이 좁아 읽기 피로 |
| C · 명세↔Issue 대조 | 좌측 작업 매핑, 우측 명세 원문 | 미등록·중복·취소가 구조적으로 드러남 | 일반 문서 탐색이 2급 |

## 사용자 결정

2026-09-09 사용자가 다음을 확정했다.

- 골격은 **B안(운영 콘솔)**.
- 서체는 **Pretendard**.
- 시각적 결은 **Codex 계열** — 단색 우선, 색은 상태에만.
- **밝은 테마 단일**. 어두운 테마는 만들지 않는다.

## 탈락 기록

A안은 읽기 품질을 화면 중심에 두는 안이었다. B안 채택으로 문서 화면의 3열 구조와 본문 68자 제한만 [UI-003](ui-screens.md)에 남기고 나머지는 채택하지 않았다.

C안은 명세와 GitHub의 어긋남을 좌우 분할로 대조하는 안이었다. B안 채택으로 분할 구조는 버리고, 작업·Issue 매핑 표와 취소/미등록의 형태 인코딩만 [UI-002](ui-screens.md)로 흡수했다.

세 방향 모두 3단 흐름(프로젝트 선택 → 현황·문서 목록 → 문서 본문)과 [API 계약](../03-tech-spec/api-spec.md)을 바꾸지 않았다. 결정으로 달라진 것은 화면 배치와 시각 언어뿐이다.

## 참고 자료

방향 비교와 화면 목업은 세션에서 만든 비공개 HTML 미리보기로 확인했다. 링크는 작성자 계정에서만 열리므로 구현 기준으로 삼지 않는다. 토큰·문구·레이아웃 수치는 모두 [공통 UI 규칙](ui-conventions.md)과 [화면 명세](ui-screens.md)에 옮겨 적었고, 두 문서만 읽고도 구현할 수 있다.

## 남은 사항

이 기록은 결정 경과만 보존한다. 아직 확정하지 않은 UI 사항은 [화면 명세](ui-screens.md)의 미확정 항목에 적는다. 여기에 중복으로 적지 않는다.
