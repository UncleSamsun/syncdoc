## 화면과 기술

- React + TypeScript. 백엔드는 Spring Boot 4 / Java 25다.
- 프로젝트 선택 → 현황과 문서 목록 → 선택한 문서 본문. 사용자가 추가 탐색 단계나 별도 목업 시연은 필요 없다고 밝혔다.
- 문서 본문·일반 표는 commonmark-java가 변환한 API html을 표시하고, 다이어그램 원문은 브라우저 Mermaid로 렌더한다.
- VitePress는 비교 뒤 Java 렌더 방식으로 대체되었다. 제품에 VitePress/별도 문서 Node 빌드를 도입하지 않는다. React 앱 빌드는 별개다.
- Mermaid 지원 범위는 흐름도·시퀀스·ERD·클래스·상태도. 오류/제한 초과는 블록 단위로 안내하고 문서 전체를 깨뜨리지 않는다.

## UI 착수 범위

frontend/가 아직 없으므로 먼저 React 실행 기반과 API client 경계를 준비한다. 백엔드가 없을 때는 API 계약과 같은 구조의 명시적인 fixture/mock adapter를 사용한다. 샘플 수치를 실제 GitHub 결과로 표시하지 않는다. 사용자의 이번 지시는 UI 우선 착수이며 전체 서버 작업의 완료를 뜻하지 않는다.

프로젝트 목록·현황·문서 목록/상세·검색과 로그인/미초대/권한 없음/첫 동기화/갱신 실패/Project 조회 불가 상태를 다룬다. 권한 없는 데이터는 mock에서도 노출하지 않는다. Project 조회 불가일 때 진행률은 null이며 0%로 대체하지 않는다. 웹 편집·Issue 생성 UI는 MVP 범위 밖이다.

API 계약 변경이 필요하면 이유와 영향을 먼저 정리한다. HTML 정화는 서버 계약이지만 fixture 역시 실행 가능한 script를 넣지 않는다. Mermaid 임의 설정을 원문에서 허용하지 않는다. frontend 작업은 frontend/와 관련 UI 명세·테스트를 중심으로 한다.

## 검증과 인수인계

React 테스트와 빌드 명령을 실제로 구성하고 결과를 남긴다. 브라우저에서 프로젝트 선택→문서 열기, 표/앵커 이동, 다이어그램5종 및 오류, 권한/빈 상태를 확인한다. 서버 연동·실제 OAuth·실계정 권한 검증은 별도로 남긴다.

main은 릴리스, dev는 통합, 구현은 dev에서 파생한 type/이슈번호-설명 브랜치에서 진행한다. 이 문서 묶음의 PR이 dev에 아직 병합되지 않았다면 승인 없이 자동 병합하지 말고 최신 문서를 포함하는 작업 기준을 확인한다. 본인 담당 영역 병합과 겹치는 영역 리뷰는 공통 GitHub 규칙을 따른다.
