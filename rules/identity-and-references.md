# ID와 문서 참조

상태: 2026-09-10 참조 방식과 문서 ID 참조 규칙 사용자 확정.

ID의 형식과 발급은 [문서 작성 규칙](spec-writing.md) §6이 정본이다. 이 문서는 그 ID로 무엇을 어떻게 참조하는지를 정한다.

## 확정 원칙

- 요구·작업 등 독립적으로 추적할 항목에는 안정적인 ID를 부여한다. 파일 이동·제목 변경 때문에 ID를 바꾸지 않는다.
- 문서 연결에는 일반 Markdown 링크를 사용하고 링크 글자에 대상 ID를 표시한다.
- `[[REQ-001]]` 같은 전용 ID 링크 문법은 MVP에서 사용하지 않는다. ID만 적힌 텍스트를 이동 가능한 링크로 간주하지 않는다.
- 같은 요구의 본문과 인수 기준은 한 곳에서 관리한다. 설계와 작업에서는 원문 링크를 사용하고 각자의 설계·구현·검증 내용만 추가한다.

## 문서 ID로 참조

문서 ID(`DOC-NNN`)는 그 문서의 안정된 식별자다. 경로가 아니라 ID가 문서의 정체성이다.

- **문서 ID는 frontmatter `id`에만 적는다.** 본문이나 제목에 다시 적지 않는다.
- **사람이 읽는 참조는 경로 링크를 쓴다.** ID는 링크를 대체하지 않는다. Markdown 링크에 경로가 필요하기 때문이다. 다만 링크 글자나 그 문장에 대상 ID를 함께 적어 어느 문서를 가리키는지 경로 없이도 알 수 있게 한다.
- **파일을 옮기면 들어오는 링크를 고치고, 대상의 `id`가 그대로인지 확인한다.** ID가 달라졌다면 다른 문서를 가리키게 된 것이다. 경로만 맞추고 넘어가지 않는다.
- **SyncDoc은 이 ID를 `documents.spec_id`에, 작업 ID를 `tasks.task_spec_id`에 저장한다.** 경로가 바뀌어도 ID로 같은 문서를 찾는다. 항목 참조를 경로에만 의존시키면 파일 이동이 곧 참조 유실이 된다. 상세는 [데이터 설계](../docs/03-tech-spec/data-model.md)를 따른다.
- **ID를 바꾸지 않고, 삭제한 ID를 다른 문서에 재사용하지 않는다.** 재사용하면 과거 참조가 조용히 다른 문서를 가리킨다.

### 어디에 무엇을 쓰는가

| 참조하는 곳 | 쓰는 것 |
|---|---|
| 저장소 안의 Markdown | 상대경로 링크 + 링크 글자에 대상 ID |
| GitHub Issue·PR 본문 | 대상 ID + GitHub에서 열리는 URL. 상대경로는 쓰지 않는다 |
| 작업 시작 기준을 고정할 때 | 대상 ID + 해당 커밋에 고정한 URL |
| SyncDoc 저장·조회 | `documents.spec_id`, `tasks.task_spec_id` |

## 작성 예시

```markdown
[REQ-001](../01-prd/requirements.md#req-001)
```

경로는 링크가 있는 문서 기준 상대경로다. 위 경로와 ID는 문법 예시이며 실제 존재하는 요구가 아니다. 실제 링크는 존재하는 파일과 대상 앵커를 확인해서 작성한다. 링크 글자는 필요하면 `REQ-001 · 저장소 연결`처럼 설명을 덧붙일 수 있다.

제목에서 생성되는 앵커는 렌더러에 따라 다를 수 있다. `REQ-001`이라는 ID가 있다는 이유만으로 `#req-001` 앵커가 존재한다고 가정하지 않는다. 실제 제목 구조와 GitHub/선택한 HTML 뷰어의 앵커 동작을 확인한다. 공통 앵커 작성 세부 방식은 뷰어 선정과 함께 검증한다.

## 파일 이동과 변경

- 파일을 이동하거나 이름을 바꾸면 해당 파일로 들어오는 링크와, 이동한 파일 안의 상대경로 링크를 함께 확인·수정한다.
- 참조 대상의 제목·앵커를 바꿀 때도 들어오는 링크를 확인한다. ID는 유지한다.
- 변경 후 파일 존재 여부와 앵커 도달 여부를 검사한다. 전용 자동 검증기가 없는 동안에는 검사 범위와 수동 확인 결과를 명시한다.
- 과거 커밋에 고정된 GitHub 링크는 당시 구현 기준을 보존하는 링크다. 최신 경로로 무조건 바꾸지 않는다.
- 원문 수정과 파생 설계 수정은 구분한다. 링크를 사용해도 변경된 요구가 코드나 설계를 자동으로 수정하지는 않는다.

## GitHub에서 참조

Issue·PR에는 GitHub에서 열 수 있는 문서 URL과 항목 ID를 남긴다. Issue 본문의 상대경로가 저장소 내 Markdown과 같다고 가정하지 않는다. 작업 시작 기준이 필요하면 해당 커밋에 고정한 URL을 사용한다.

## 현재 적용 범위

이 규칙은 참조 방식의 정본이다. ID 접두어·발급 충돌 처리·frontmatter 필드의 전체 규약을 확정한 문서는 아니다. 자동 링크 검사기와 HTML 렌더러는 아직 구현하지 않았다.
