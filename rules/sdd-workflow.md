# SDD 역할과 승인 범위

상태: 2026-09-09 사용자 확정

## 역할

| 단계 | 에이전트 | 사람 |
|---|---|---|
| 요구·설계 | 초안 작성, 대안과 미결 사항 제시 | 범위와 주요 설계 확정 |
| 작업 준비 | 작업 분해, Issue·Project 등록 준비와 승인된 계획의 등록 | 작업계획 확인 |
| 구현 | 브랜치 작업, 테스트, PR 작성 | 필요한 질문과 범위 변경 판단 |
| 완료 | 검증 결과와 변경 내용 정리 | PR 최종 검토와 병합 판단 |

## 진행 원칙

- 승인된 작업 범위 안에서는 구현과 검증을 계속 진행한다. 사소한 수정마다 승인을 반복해서 요청하지 않는다.
- 요구·주요 설계·작업 범위를 바꾸어야 하면 변경 이유와 영향을 정리해 확인받는다. 영향이 없는 독립 작업은 계속 진행할 수 있다.
- 사람은 검토 가능한 명세·작업계획·PR·검증 결과를 기준으로 판단한다. 아직 구체화되지 않은 결과의 승인을 요청하지 않는다.
- 병합 판단은 사람에게 있다. PR 작성과 테스트 통과를 병합 승인으로 해석하지 않는다.
- 승인된 계획의 GitHub 등록·PR 작성은 에이전트 역할에 포함된다. 대상 저장소와 작업 범위가 확정되어 있어야 한다. 이 규칙을 무관한 메시지 전송이나 저장소 변경의 권한으로 확장하지 않는다.
- 검증하지 않은 기능을 완료로 표시하지 않는다. 실패·미실행·남은 작업은 구분해서 보고한다.

GitHub 상태·브랜치·담당 영역별 리뷰·병합은 [GitHub 협업 규칙](github-collaboration.md)을 따른다. 개인·팀 모두 본인 담당 범위는 직접 병합할 수 있고 다른 담당자 영역과 겹치면 관련 담당자 리뷰를 받는다. 이것은 에이전트의 자율 병합 권한을 뜻하지 않는다. ID 세부 형식은 별도 검토 중이다.
