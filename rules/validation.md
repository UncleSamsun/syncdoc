# 검증 규칙

상태: 2026-09-10 사용자 확정 · 활성 규칙

[문서 작성 규칙](spec-writing.md)을 기계로 검사하는 기준이다. 검사 대상 문서와 필수 내용의 정의는 그 파일에 있고 여기서 반복하지 않는다.

## 1. 구현 상태

**검증기는 아직 구현되지 않았다.** `tools/spec-validator/`는 [TASK-004](../docs/04-tasks/implementation-plan.md)의 후속 PR에서 만든다. 그때까지 이 문서의 검사 항목은 사람이 리뷰에서 확인하고, 어떤 문서도 "검증 통과"로 표시하지 않는다.

구현 후에는 이 절을 실제 실행 명령과 지원 범위로 교체한다. 존재하지 않는 검사기를 통과했다고 쓰지 않는다.

## 2. 검사 항목

| # | 검사 | 판정 |
|---|---|---|
| V1 | frontmatter 존재와 필드 | `id`·`type`·`status` 세 필드가 모두 있고 허용 값인지. 네 번째 필드가 있으면 오류 |
| V2 | 문서 ID 형식과 유일성 | `DOC-NNN` 형식이며 프로젝트 안에서 중복되지 않는지 |
| V3 | 항목 ID 형식과 유일성 | 등록된 접두어(`REQ`·`UI`·`TASK`)만 쓰고, 같은 접두어의 번호가 프로젝트 안에서 중복되지 않는지 |
| V4 | 필수 라벨 | `type`별 검사 단위마다 요구되는 굵은 라벨이 있는지. 라벨만 있고 같은 줄에 내용이 없으면 오류 |
| V5 | 파일 링크 도달 | 상대 링크의 대상 파일이 존재하는지 |
| V6 | 앵커 도달 | 링크의 `#앵커`가 대상 문서의 제목에서 생성되는 앵커와 일치하는지 |
| V7 | 이미지 경로 | 상대 이미지 경로의 대상 파일이 존재하는지. 파일 이동 후 깨진 경로를 잡는다 |

## 3. 검사에서 제외하는 것

- **코드 블록과 인라인 코드 안의 링크·ID.** 문법 예시로 존재하지 않는 경로를 적는 경우가 실제로 있다. `rules/identity-and-references.md`의 `../01-prd/requirements.md`가 그 예이며 그 문서는 "실제 존재하는 요구가 아니다"라고 명시한다. 코드 블록을 검사하면 오탐이 된다.
- **외부 URL의 도달 여부.** `http`·`https` 링크는 형식만 보고 접속하지 않는다. 네트워크 상태에 따라 결과가 달라지는 검사를 넣지 않는다.
- **과거 커밋에 고정한 GitHub 링크.** 당시 기준을 보존하는 링크이므로 현재 경로와 다른 것이 정상이다.
- **`type: note` 문서의 필수 라벨.** V4를 적용하지 않는다. V1·V2·V5·V6·V7은 적용한다.

## 4. 실행 시점

- 문서를 고친 PR을 올리기 전에 실행한다.
- 문서 PR을 병합하기 전에 결과를 확인한다.
- 파일을 이동하거나 이름을 바꾼 직후에 실행한다. V5·V6·V7이 이때 가장 많이 걸린다.
- 규칙 파일을 고친 뒤에 실행한다. 규칙 변경이 기존 문서를 위반 상태로 만들 수 있다.

CI 연결은 아직 하지 않는다. 실행 환경과 워크플로는 [프로젝트 설정](project-settings.md)에서 확정한 뒤 이 절을 고친다.

## 5. 실패 처리

- 검사 결과는 **오류**와 **경고**로 나눈다. 오류는 병합을 막고, 경고는 사유를 PR에 적으면 병합할 수 있다.
- V1·V2·V3·V4·V5는 오류다. 문서의 정체성과 필수 내용, 끊어진 참조는 그냥 두지 않는다.
- V6·V7은 경고다. 앵커는 렌더러에 따라 다를 수 있고 이미지는 외부에서 관리될 수 있다. 사유를 적지 않으면 오류로 취급한다.
- 출력은 `파일:줄 [검사ID] 내용` 형식으로 위치를 특정한다. 어느 파일의 어느 항목이 왜 걸렸는지 알 수 없는 출력은 실패로 본다.
- 검사 대상 문서가 하나도 없으면 통과가 아니라 **미검사**로 보고한다.
- 규칙 파일(`rules/spec-writing.md`)이 없는 프로젝트는 **미검사**로 보고한다. 검사할 기준이 없는 상태를 통과로 표시하지 않는다.

## 6. 검증기가 지켜야 할 것

- 표준 라이브러리만 쓴다. 외부 의존성을 추가하지 않는다.
- 문서를 고치지 않는다. 읽고 보고만 한다. 자동 수정을 넣지 않는다.
- 검사 항목을 늘릴 때 이 문서의 표를 먼저 고친다. 문서에 없는 검사를 코드에만 넣지 않는다.
- 오류가 재현되는 테스트를 먼저 만들고 통과시킨다. 검사 항목마다 정상 fixture와 실패 fixture를 둔다.
