# 규칙 fixture

C0 비교 대상인 세 표만 둔다. 표 밖 산문은 검사하지 않는다.

## 3. 문서 종류와 필수 내용

| type | 문서 종류 | 적용 조건 | 필수 내용 |
|---|---|---|---|
| `prd-overview` | 프로젝트 개요 | 모든 프로젝트 | 문제, 대상 사용자, 목표, 성공 판단, 포함 범위, 제외 범위, 제약, 적용 Spec, 용어 |
| `prd-requirements` | 기능·품질 요구 | 모든 프로젝트 | 요구 ID, 사용자 필요, 기대 동작과 품질 조건, 예외, 인수 기준, 근거 |
| `ui-conventions` | 공통 UI 규칙 | 사용자 화면이 있으면 | 색·글자·간격 토큰, 공통 컴포넌트, 탐색, 접근성, 공통 상태 표현 |
| `ui-screens` | 화면 명세 | 사용자 화면이 있으면 | 화면 ID, 연결 요구, 진입·종료 경로, 레이아웃, 사용자 행동, 로딩·빈 상태·오류·권한 상태, 화면 고유 검증 |
| `tech-overview` | 기술 개요 | 모든 프로젝트 | 시스템 경계, 모듈 책임·의존성, 외부 연동, 주요 흐름, 기술 선택과 이유, 검증 전략 |
| `tech-interface` | 인터페이스 계약 | API·이벤트·파일 경계가 있으면 | 계약 ID, 연결 요구, 입력, 출력, 오류, 접근 조건, 부작용, 재시도·중복 처리 |
| `tech-data` | 데이터 설계 | 영속 데이터가 있으면 | 엔티티, 필드 의미, 키·관계·제약, 수명, 변경·마이그레이션 |
| `tech-ops` | 실행·운영 | 배포·호스팅 또는 지속 실행 작업이 있으면 | 실행 환경, 설정·비밀값 주입, 배포, 상태 확인, 장애·복구, 백업 대상 또는 불필요 사유 |
| `tasks` | 작업 정의 | 구현 대상으로 정한 기능 | 작업 ID, 목적, 연결 요구·설계, 포함·제외 범위, 선행 작업, 산출물, 검증 방법, 완료 조건 |
| `proposal` | 검토 초안 | 확정 전 대안을 정리할 때 | 무엇을 제안하는지와 확정되지 않은 항목 |
| `record` | 경과 기록 | 결정 경위를 남길 때 | 결정한 내용과 근거, 어느 문서가 정본인지 |
| `guide` | 안내 | 읽는 방법·착수 방법을 알릴 때 | 대상과 먼저 읽을 문서 |

## 5. 필수 내용 표기

### 라벨 이름 공간

| type | 허용하는 굵은 라벨 |
|---|---|
| `prd-overview` | 문제, 대상 사용자, 목표, 성공 판단, 포함 범위, 제외 범위, 제약, 적용 Spec, 용어 |
| `prd-requirements` | 사용자 필요, 기대 동작, 예외, 인수 기준, 근거 |
| `ui-screens` | 연결 요구, 진입, 종료, 레이아웃, 사용자 행동, 상태, 검증, 관련 작업 |
| `tasks` | 목적, 근거, 범위, 선행, 산출물, 검증, 완료 |
| `tech-interface` | 연결 요구, 입력, 출력, 오류, 접근 조건, 부작용, 재시도 |

| type | 검사 단위 | 검사기가 요구하는 라벨 |
|---|---|---|
| `prd-overview` | 문서 | `문제`, `대상 사용자`, `목표`, `성공 판단`, `포함 범위`, `제외 범위`, `제약`, `적용 Spec`, `용어` |
| `prd-requirements` | `## REQ-NNN` 섹션마다 | `예외`, `인수 기준`, `근거` |
| `ui-screens` | `## UI-NNN` 섹션마다 | `연결 요구`, `검증` |
| `tasks` | `## TASK-NNN` 섹션마다 | `근거`, `선행`, `산출물`, `검증`, `완료` |
| `tech-interface` | `## 계약 일람` 표의 행마다 | `ID` 열과 `연결 요구` 열이 채워짐 |
| `tech-interface` | 문서 | `접근 조건`, `부작용`, `재시도` |
